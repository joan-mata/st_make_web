🔍 DevTools del Navegador

Todos los navegadores modernos incluyen herramientas de desarrollo potentes y completamente gratuitas. Dominarlas te permitirá depurar HTML, CSS y JavaScript, analizar el rendimiento y entender cómo funciona cualquier página web.

1. ¿Qué son las DevTools?

Las DevTools (herramientas de desarrollador) son un conjunto de utilidades integradas en el navegador que permiten inspeccionar, depurar y analizar páginas web en tiempo real. Están disponibles en Chrome, Firefox, Safari, Edge y cualquier navegador moderno.

No necesitas instalar nada: ya las tienes. Solo tienes que abrirlas.

Cómo abrirlas

MétodoAcción
Teclado F12 — abre/cierra las DevTools
Teclado Ctrl+Shift+I (Windows/Linux) · Cmd+Option+I (Mac)
Menú contextual Clic derecho en cualquier elemento → Inspeccionar
Menú del navegador Menú → Más herramientas → Herramientas para desarrolladores
💡 Consejo El atajo Ctrl+Shift+C activa directamente el modo "selector de elementos" — pasa el ratón por la página y haz clic en cualquier elemento para inspeccionarlo sin tener que abrir las DevTools primero.

Las DevTools se organizan en paneles. Los más importantes son: Elements, Console, Network, Sources y Application. Cada uno tiene un propósito específico que exploraremos en detalle.

2. El Panel Elements (Inspector)

El panel Elements (llamado Inspector en Firefox) es el más usado. Muestra el árbol DOM en vivo de la página: el HTML tal como lo interpreta el navegador en este momento, incluyendo los cambios que JavaScript haya podido hacer.

Qué puedes hacer en Elements

Seleccionar un elemento

Haz clic en el icono de cursor (esquina superior izquierda de las DevTools) o pulsa Ctrl+Shift+C, luego haz clic en cualquier elemento de la página. El DOM se desplazará automáticamente hasta ese nodo.

Editar HTML en vivo

Haz doble clic sobre cualquier nodo del árbol DOM para editarlo directamente. Los cambios se aplican al instante (pero solo en memoria — al recargar la página se pierden). Esto es perfecto para probar ideas sin tocar los archivos.

El panel Styles (Estilos)

A la derecha del árbol DOM verás el panel Styles. Muestra todos los estilos CSS que se aplican al elemento seleccionado, con la fuente (qué archivo y qué línea) y si alguno está sobreescrito (aparece tachado).

  • Puedes activar/desactivar reglas haciendo clic en el checkbox a la izquierda.
  • Puedes editar valores haciendo clic sobre ellos.
  • Puedes añadir nuevas propiedades haciendo clic al final de un bloque.
  • En propiedades de color aparece un pequeño cuadrado de color — haz clic para abrir el selector de color visual.
🎨 Selector de color integrado Al hacer clic en el cuadrado de color junto a una propiedad CSS, se abre un selector de color completo con pipeta (para muestrear colores de la pantalla), paleta y conversión entre formatos. Manteniendo Shift y haciendo clic en el cuadrado, ciclas entre formatos: hex → rgb → hsl.

El sub-panel Computed (Calculado)

La pestaña Computed muestra los valores finales calculados de todas las propiedades CSS, después de aplicar herencia, especificidad y valores por defecto. También incluye una representación visual del modelo de caja (margin, border, padding, content) con las dimensiones exactas en píxeles.

Forzar estados de elementos

En el panel Styles, busca el botón :hov. Al hacer clic, aparece un menú para forzar el estado :hover, :focus, :active, :visited o :focus-within. Esto es muy útil para depurar estilos de hover sin tener que mantener el ratón encima del elemento.

Copiar selector o HTML

Clic derecho sobre un nodo del DOM → Copy → opciones:

  • Copy element — copia el HTML completo del nodo y sus hijos.
  • Copy selector — genera el selector CSS único para ese elemento.
  • Copy JS path — genera el código JavaScript para acceder al elemento.
  • Copy XPath — la ruta XPath (útil para automatización con Selenium).
📌 El DOM vs. el HTML fuente Lo que ves en Elements NO es exactamente el HTML de tu archivo. Es el DOM procesado por el navegador. JavaScript puede haber añadido o eliminado elementos, el navegador puede haber corregido errores de HTML… El código fuente real lo ves con Ctrl+U.

3. El Panel Console

La Consola es un REPL de JavaScript (Read-Eval-Print Loop): puedes escribir código JS y ejecutarlo directamente en el contexto de la página actual. También es donde aparecen todos los errores y mensajes de depuración.

Métodos de console

// Mostrar información
console.log('Hola desde JS');
console.log('Usuario:', usuario);         // Múltiples argumentos

// Avisos y errores
console.warn('⚠️ Esto es un aviso');
console.error('❌ Algo salió mal');

// Mostrar datos en forma de tabla (muy útil para arrays de objetos)
const usuarios = [
  { nombre: 'Ana',   edad: 22 },
  { nombre: 'Luis',  edad: 25 },
];
console.table(usuarios);

// Agrupar mensajes
console.group('Datos del formulario');
console.log('nombre:', nombre);
console.log('email:', email);
console.groupEnd();

// Medir tiempo de ejecución
console.time('mi-operacion');
// ... código que quieres medir ...
console.timeEnd('mi-operacion');  // muestra el tiempo transcurrido

Atajos de la consola

La consola incluye varios atajos que no existen en JS normal:

// $0 = el elemento actualmente seleccionado en el panel Elements
console.log($0);
$0.style.border = '2px solid red';   // ¡modificamos el elemento seleccionado!

// $() = alias de document.querySelector()
$('h1').textContent = 'Cambiado desde la consola';

// $$() = alias de document.querySelectorAll() (devuelve array real)
$$('p').forEach(p => console.log(p.textContent));

// copy() = copia una variable al portapapeles
const datos = { nombre: 'Ana', edad: 22 };
copy(datos);  // ahora puedes pegar el JSON donde quieras

// monitorEvents() = muestra todos los eventos de un elemento
monitorEvents(document.body, 'click');
unmonitorEvents(document.body);   // para de monitorizar
💡 Consola multi-línea Para escribir varias líneas en la consola, pulsa Shift+Enter en lugar de Enter. Así puedes escribir funciones enteras antes de ejecutarlas.

Ver errores de PHP en la consola

Los errores de PHP no aparecen en la consola de JavaScript — aparecen en el HTML que genera PHP. Sin embargo, si tu PHP hace una petición AJAX, el error puede aparecer en el panel Network (en la respuesta de la petición). Para ver errores PHP en el navegador, asegúrate de que display_errors esté activado en tu configuración de PHP durante el desarrollo.

4. El Panel Network

El panel Network registra todas las peticiones HTTP que hace el navegador: el HTML inicial, los archivos CSS y JS, las imágenes, las fuentes, y las llamadas AJAX/Fetch a APIs o scripts PHP.

📌 Importante El panel Network solo registra peticiones mientras está abierto. Si abres las DevTools después de cargar la página, no verás las peticiones iniciales. Activa la opción "Preserve log" para que no se borre al navegar a otra página.

Qué ves en cada petición

Haz clic en cualquier fila para ver el detalle:

  • Headers — cabeceras de la petición (enviadas) y de la respuesta (recibidas): tipo de contenido, cookies, caché, CORS…
  • Response — el cuerpo de la respuesta. Si tu PHP devuelve JSON, aquí lo verás. Si hay un error de PHP, también aparece aquí.
  • Preview — vista previa formateada (muy útil para JSON).
  • Timing — desglose del tiempo: DNS, TCP, espera del servidor, descarga.

Códigos de estado HTTP

CódigoSignificadoCuándo ocurre
200 OK Éxito La petición funcionó correctamente
301 / 302 Redirección El recurso se ha movido (permanente/temporal)
304 Not Modified Sin cambios El navegador usa la versión en caché
404 Not Found No encontrado El archivo o recurso no existe en el servidor
500 Server Error Error del servidor Error en PHP, base de datos caída, etc.
403 Forbidden Prohibido No tienes permisos para acceder al recurso

Filtrar peticiones

Usa la barra de filtros para ver solo ciertos tipos de peticiones:

  • All — todas las peticiones
  • Fetch/XHR — llamadas AJAX (tu PHP con fetch())
  • JS — archivos JavaScript
  • CSS — hojas de estilo
  • Img — imágenes
  • Doc — documentos HTML

Throttling (simular conexión lenta)

El menú desplegable "No throttling" permite simular distintas velocidades de conexión: Fast 3G, Slow 3G, Offline… Ideal para comprobar cómo se comporta tu web en dispositivos móviles con conexión lenta.

💡 Ver qué devuelve tu PHP Cuando haces una petición Fetch a un script PHP, ve a Network → filtra por Fetch/XHR → selecciona la petición → pestaña Response. Verás exactamente lo que PHP devolvió, incluyendo cualquier error o mensaje de var_dump() que hayas dejado olvidado.

5. El Panel Sources

El panel Sources es el depurador de JavaScript del navegador. Permite pausar la ejecución del código y examinarlo línea a línea, lo que es infinitamente más potente que llenar el código de console.log().

Puntos de ruptura (Breakpoints)

Un breakpoint detiene la ejecución en una línea concreta. Para añadir uno:

  1. Abre Sources → busca tu archivo JS en el panel izquierdo.
  2. Haz clic en el número de línea donde quieras pausar.
  3. Aparecerá un marcador azul en esa línea.
  4. Recarga la página o ejecuta la acción que dispara ese código.
  5. La ejecución se detendrá en esa línea.

Controles de depuración

BotónAtajoQué hace
▶ Resume F8 Continúa la ejecución hasta el siguiente breakpoint
⤼ Step over F10 Ejecuta la línea actual y va a la siguiente (sin entrar en funciones)
↓ Step into F11 Entra dentro de la función que se está llamando
↑ Step out Shift+F11 Sale de la función actual

Inspeccionar variables en pausa

Cuando la ejecución está pausada puedes:

  • Pasar el ratón sobre cualquier variable para ver su valor actual.
  • Ver el panel Scope (ámbito): todas las variables locales y globales disponibles.
  • Ver el panel Call Stack: la cadena de funciones que llevaron hasta aquí.
  • Añadir expresiones a Watch para monitorizar su valor.

El atajo debugger

Añadir debugger; en tu código JavaScript tiene el mismo efecto que un breakpoint, pero directamente en el código: 

function calcularTotal(items) {
  debugger;  // la ejecución se pausará aquí (solo si DevTools está abierto)
  const total = items.reduce((suma, item) => suma + item.precio, 0);
  return total;
}
📌 Recuerda eliminar los debugger La sentencia debugger; solo pausa si las DevTools están abiertas, pero es una mala práctica dejarla en código de producción. Elimínala antes de subir al servidor.

6. El Panel Application

El panel Application da acceso al almacenamiento del navegador para el dominio actual. Es donde puedes ver y editar cookies, LocalStorage, SessionStorage y la caché.

LocalStorage y SessionStorage

Ambos almacenan datos como pares clave-valor en el navegador del usuario, sin necesidad de servidor. La diferencia es su duración:

LocalStorageSessionStorage
Duración Permanente (hasta que el usuario o JS lo borre) Solo durante la sesión del navegador (se borra al cerrar la pestaña)
Capacidad ~5-10 MB ~5-10 MB
Acceso Solo desde JavaScript Solo desde JavaScript 
// Guardar en LocalStorage
localStorage.setItem('usuario', 'Ana');
localStorage.setItem('preferencias', JSON.stringify({ tema: 'oscuro' }));

// Leer
const nombre = localStorage.getItem('usuario');
const prefs  = JSON.parse(localStorage.getItem('preferencias'));

// Eliminar
localStorage.removeItem('usuario');
localStorage.clear();  // elimina todo

En el panel Application puedes ver todos los valores almacenados, editarlos o eliminarlos directamente, sin necesidad de código.

Cookies

Las cookies también aparecen en Application → Cookies. Para cada cookie verás su nombre, valor, dominio, ruta, fecha de expiración y flags de seguridad (HttpOnly, Secure, SameSite). Las cookies HttpOnly no son accesibles desde JavaScript — solo el servidor puede leerlas y escribirlas.

💡 Limpiar el estado de la aplicación Cuando algo raro pase con tu app y sospeches que hay datos antiguos en el almacenamiento, ve a Application → Storage → haz clic en "Clear site data" para borrar todo de una vez.

7. Trucos rápidos

Atajos de teclado esenciales

AtajoQué hace
F12 Abrir/cerrar DevTools
Ctrl+Shift+I Abrir DevTools (mismo que F12)
Ctrl+Shift+C Activar modo selector de elementos
Ctrl+Shift+J Abrir DevTools directamente en la Consola
Ctrl+P (dentro de DevTools) Buscar y abrir un archivo del proyecto
Ctrl+Shift+P (dentro de DevTools) Paleta de comandos (como VS Code)
Escape Abrir/cerrar el cajón de la consola en cualquier panel
Ctrl+R / Ctrl+Shift+R Recargar / Recargar sin caché (hard reload)

Trucos con CSS y elementos

  • Mantén Shift + clic en un cuadrado de color para ciclar entre formatos: hex → rgb → hsl → hwb.
  • Doble clic en un valor numérico CSS (ej. 16px) y usa las teclas ↑ ↓ para incrementar/decrementar de uno en uno. Con Shift+↑ incrementa de 10 en 10.
  • Clic derecho en un elemento → "Scroll into view" para desplazar la página hasta ese elemento aunque esté fuera de la vista.
  • Clic derecho en un elemento → "Force state" para forzar estados CSS sin usar el botón :hov.
  • Clic derecho en un elemento → "Break on" → "Subtree modifications" para añadir un DOM breakpoint: la ejecución se pausará cuando JavaScript modifique los hijos de ese elemento.

Trucos con la consola

  • performance.now() devuelve el tiempo en milisegundos desde que se cargó la página. Úsalo para medir el tiempo de ejecución de un fragmento de código.
  • Escribe %c en un console.log() para aplicar estilos CSS al texto de la consola: console.log('%c¡Hola!', 'color: red; font-size: 20px').
  • La consola recuerda el historial: pulsa ↑ para recuperar comandos anteriores.
💡 Hard reload sin caché Si cambias un archivo CSS o JS y no ves los cambios, el navegador puede estar usando la versión en caché. Con las DevTools abiertas, haz clic derecho en el botón de recarga → "Empty cache and hard reload".

8. Extensiones útiles para el navegador

Aunque no forman parte de las DevTools, estas extensiones se integran con ellas y son muy útiles para el desarrollo web:

ExtensiónPara qué sirve
WhatFont Detecta la fuente tipográfica de cualquier texto en la página con solo pasar el ratón por encima.
ColorZilla Pipeta de color que puede muestrear el color exacto de cualquier píxel de la pantalla. Incluye historial de colores.
Wappalyzer Detecta las tecnologías usadas en cualquier web: framework JS, CMS, servidor web, CDN, analytics…
React DevTools Añade un panel "Components" a las DevTools para inspeccionar el árbol de componentes React y su estado.
Vue DevTools Igual que React DevTools pero para Vue.js. Muy útil cuando empieces a usar frameworks JS.
JSON Formatter Formatea y colorea las respuestas JSON cuando las abres directamente en el navegador.
📌 Para el futuro React DevTools y Vue DevTools solo son útiles si estás desarrollando con esos frameworks. Por ahora, WhatFont, ColorZilla y Wappalyzer son las más útiles para el día a día con HTML/CSS/PHP.

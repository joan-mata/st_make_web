🗄️ Base de Datos

PostgreSQL es un potente sistema de bases de datos relacional de código abierto. Aquí aprenderás a diseñar tablas, escribir SQL y conectar PHP a la base de datos de forma segura.

1. ¿Qué es una base de datos relacional?

Una base de datos relacional organiza la información en tablas con filas y columnas, igual que una hoja de cálculo, pero con la potencia de relacionar tablas entre sí y consultar millones de registros en milisegundos.

El lenguaje estándar para interactuar con estas bases de datos es SQL (Structured Query Language). Todos los sistemas relacionales (PostgreSQL, MySQL, SQLite, SQL Server…) lo usan con variaciones menores.

PostgreSQL es uno de los sistemas más completos y fiables: más de 35 años de desarrollo activo, completamente gratuito y de código abierto. Lo usan empresas como Apple, Instagram, Spotify y Reddit.

3. PostgreSQL: instalación y herramientas

Instalar PostgreSQL

  • Windows / macOS: descarga el instalador desde postgresql.org/download. Incluye el servidor y pgAdmin 4.
  • macOS (alternativa): brew install postgresql@16 (con Homebrew).
  • Linux (Ubuntu/Debian): sudo apt install postgresql postgresql-contrib.

Herramientas principales

📌 Habilitar PDO PostgreSQL en XAMPP
  1. Abre el archivo php.ini (desde el panel de XAMPP → PHP → php.ini).
  2. Busca la línea ;extension=pdo_pgsql.
  3. Quita el punto y coma: extension=pdo_pgsql.
  4. Reinicia Apache desde el panel de XAMPP.
  5. Verifica con <?php phpinfo(); ?> que aparece "PDO drivers: pgsql".

4. SQL: el lenguaje de las bases de datos

4.1 CREATE DATABASE y CREATE TABLE

Antes de guardar datos necesitamos definir la estructura: qué tablas existen y qué tipo de dato almacena cada columna. 

-- Crear la base de datos (desde psql o pgAdmin)
CREATE DATABASE mi_proyecto
  WITH ENCODING 'UTF8'
       LC_COLLATE = 'es_ES.UTF-8'
       TEMPLATE = template0;

-- Conectarse a la base de datos (en psql)
\c mi_proyecto

-- ── Tipos de datos más usados en PostgreSQL ──────────────────
-- SERIAL          → entero auto-incremental (1, 2, 3…)
-- INTEGER / INT   → número entero
-- BIGINT          → entero grande (para IDs de tablas muy grandes)
-- DECIMAL(10,2)   → número decimal (p. ej: precios)
-- VARCHAR(n)      → texto de longitud máxima n caracteres
-- TEXT            → texto de longitud ilimitada
-- BOOLEAN         → true / false
-- DATE            → solo fecha (2025-09-01)
-- TIMESTAMP       → fecha y hora (2025-09-01 10:23:45)
-- UUID            → identificador único universal

-- ── Crear tabla usuarios ──────────────────────────────────────
CREATE TABLE usuarios (
    id            SERIAL PRIMARY KEY,
    nombre        VARCHAR(100) NOT NULL,
    email         VARCHAR(255) NOT NULL UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    edad          INTEGER      CHECK (edad >= 0 AND edad <= 120),
    activo        BOOLEAN      DEFAULT TRUE,
    created_at    TIMESTAMP    DEFAULT NOW()
);

-- ── Crear tabla posts (con FOREIGN KEY) ───────────────────────
CREATE TABLE posts (
    id         SERIAL PRIMARY KEY,
    titulo     VARCHAR(200) NOT NULL,
    contenido  TEXT,
    -- La FK vincula cada post a un usuario existente
    usuario_id INTEGER NOT NULL REFERENCES usuarios(id) ON DELETE CASCADE,
    created_at TIMESTAMP DEFAULT NOW()
);
-- ON DELETE CASCADE: si se elimina un usuario, se eliminan sus posts

-- Ver las tablas creadas (en psql)
\dt

4.2 INSERT — Insertar datos

-- Insertar un único registro
INSERT INTO usuarios (nombre, email, password_hash, edad)
VALUES ('Ana García', 'ana@uni.es', '$2y$10$hash_bcrypt_aqui', 22);

-- Insertar varios registros a la vez
INSERT INTO usuarios (nombre, email, password_hash) VALUES
    ('Marc López',  'marc@uni.es',  '$2y$10$hash1'),
    ('Laia Puig',   'laia@uni.es',  '$2y$10$hash2'),
    ('Jordi Roca',  'jordi@uni.es', '$2y$10$hash3');

-- Insertar y recuperar el ID generado (útil en PHP)
INSERT INTO usuarios (nombre, email, password_hash)
VALUES ('Pedro Gil', 'pedro@uni.es', '$2y$10$hashxyz')
RETURNING id;   -- PostgreSQL devuelve el id asignado

4.3 SELECT — Consultar datos

-- Todos los registros de la tabla
SELECT * FROM usuarios;

-- Solo ciertas columnas
SELECT id, nombre, email FROM usuarios;

-- Filtrar con WHERE
SELECT * FROM usuarios WHERE activo = TRUE;
SELECT * FROM usuarios WHERE edad >= 18 AND edad <= 25;
SELECT * FROM usuarios WHERE nombre LIKE 'Ana%';      -- empieza por "Ana"
SELECT * FROM usuarios WHERE email ILIKE '%@uni.es';  -- insensible a mayúsculas

-- Ordenar resultados
SELECT * FROM usuarios ORDER BY nombre ASC;
SELECT * FROM usuarios ORDER BY created_at DESC;

-- Paginación (LIMIT + OFFSET)
SELECT * FROM usuarios ORDER BY id LIMIT 10 OFFSET 0;   -- página 1 (10 registros)
SELECT * FROM usuarios ORDER BY id LIMIT 10 OFFSET 10;  -- página 2

-- Contar registros
SELECT COUNT(*) FROM usuarios;
SELECT COUNT(*) FROM usuarios WHERE activo = TRUE;

-- ── INNER JOIN: combina filas de dos tablas ───────────────────
-- Muestra todos los posts junto con el nombre de su autor
SELECT
    u.nombre        AS autor,
    u.email,
    p.titulo,
    p.created_at
FROM posts p
INNER JOIN usuarios u ON u.id = p.usuario_id
WHERE u.activo = TRUE
ORDER BY p.created_at DESC;

-- ── LEFT JOIN: incluye también usuarios sin posts ─────────────
SELECT
    u.nombre,
    COUNT(p.id) AS total_posts
FROM usuarios u
LEFT JOIN posts p ON p.usuario_id = u.id
GROUP BY u.id, u.nombre
ORDER BY total_posts DESC;

4.4 UPDATE — Actualizar datos

-- Actualizar un campo específico
UPDATE usuarios
SET nombre = 'Ana García Martínez'
WHERE id = 1;

-- Actualizar varios campos a la vez
UPDATE usuarios
SET nombre = 'Marc L.',
    activo = FALSE
WHERE id = 2;

-- ⚠️ ATENCIÓN: sin WHERE se actualizan TODOS los registros
UPDATE usuarios SET activo = TRUE;  -- ¡Activa a TODOS!

4.5 DELETE — Eliminar datos

-- Eliminar un registro concreto
DELETE FROM usuarios WHERE id = 3;

-- Eliminar según condición
DELETE FROM usuarios WHERE activo = FALSE AND created_at < NOW() - INTERVAL '1 year';

-- ⚠️ ATENCIÓN: sin WHERE se eliminan TODOS los registros
DELETE FROM usuarios;  -- ¡Vacía la tabla por completo!

5. Relaciones entre tablas

El poder de las bases de datos relacionales está en cómo conectan tablas entre sí. Hay tres tipos de relaciones:

5.1 Uno a Uno (1:1)

Un registro de la tabla A corresponde a exactamente un registro de la tabla B. Poco frecuente; se usa para separar datos sensibles o muy grandes. 

-- Ejemplo: un usuario tiene un único perfil extendido
CREATE TABLE perfiles (
    id         SERIAL PRIMARY KEY,
    usuario_id INTEGER NOT NULL UNIQUE REFERENCES usuarios(id) ON DELETE CASCADE,
    bio        TEXT,
    avatar_url VARCHAR(500),
    web        VARCHAR(500)
);
-- La restricción UNIQUE en usuario_id garantiza la relación 1:1

5.2 Uno a Muchos (1:N) — la más común

Un registro de la tabla A puede tener muchos registros relacionados en la tabla B, pero cada registro de B pertenece a exactamente uno de A. 

-- Ejemplo: un usuario tiene muchos posts; cada post pertenece a un usuario
-- (ya visto antes con la tabla posts)

-- Otro ejemplo: un producto pertenece a una categoría, pero una categoría
-- tiene muchos productos
CREATE TABLE categorias (
    id     SERIAL PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL
);

CREATE TABLE productos (
    id           SERIAL PRIMARY KEY,
    nombre       VARCHAR(200) NOT NULL,
    precio       DECIMAL(10,2) NOT NULL CHECK (precio >= 0),
    categoria_id INTEGER REFERENCES categorias(id) ON DELETE SET NULL
);
-- ON DELETE SET NULL: si se elimina la categoría, el campo queda a NULL
-- (en lugar de eliminar también los productos)

5.3 Muchos a Muchos (N:M)

Un registro de A puede relacionarse con muchos de B, y viceversa. Se implementa con una tabla intermedia (o "tabla pivote"). 

-- Ejemplo: un estudiante puede matricularse en muchos cursos,
-- y un curso puede tener muchos estudiantes

CREATE TABLE cursos (
    id     SERIAL PRIMARY KEY,
    nombre VARCHAR(200) NOT NULL,
    creditos INTEGER DEFAULT 3
);

-- Tabla pivote: matrícula (estudiante ↔ curso)
CREATE TABLE matriculas (
    -- PK compuesta (combinación de los dos IDs debe ser única)
    estudiante_id INTEGER NOT NULL REFERENCES usuarios(id) ON DELETE CASCADE,
    curso_id      INTEGER NOT NULL REFERENCES cursos(id)   ON DELETE CASCADE,
    fecha_alta    DATE DEFAULT CURRENT_DATE,
    nota          DECIMAL(4,2),
    PRIMARY KEY (estudiante_id, curso_id)  -- PK compuesta
);

-- Consultar los cursos de un estudiante
SELECT c.nombre, c.creditos, m.nota
FROM matriculas m
INNER JOIN cursos c ON c.id = m.curso_id
WHERE m.estudiante_id = 1
ORDER BY c.nombre;

6. El fichero de conexión — config/database.php

PDO (PHP Data Objects) es la extensión de PHP recomendada para conectarse a bases de datos. Su ventaja principal es que funciona con múltiples bases de datos con el mismo código y gestiona automáticamente la protección contra SQL Injection con los prepared statements. 

<?php
// config/database.php
// NUNCA pongas credenciales reales aquí si vas a subir esto a GitHub.
// Usa variables de entorno (ver sección 8 y la guía de Seguridad).

function getConexion(): PDO {
    // Lee los valores de las variables de entorno (definidas en .env)
    $host   = getenv('DB_HOST')     ?: 'localhost';
    $port   = getenv('DB_PORT')     ?: '5432';
    $dbname = getenv('DB_NAME')     ?: 'mi_proyecto';
    $user   = getenv('DB_USER')     ?: 'postgres';
    $pass   = getenv('DB_PASSWORD') ?: '';

    // DSN: cadena que identifica la base de datos y su configuración
    $dsn = "pgsql:host=$host;port=$port;dbname=$dbname;options='--client_encoding=UTF8'";

    $opciones = [
        // Lanzar excepciones cuando ocurra un error (en lugar de errores silenciosos)
        PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
        // Devolver arrays asociativos por defecto (columna => valor)
        PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
        // Usar prepared statements reales (más seguro con PostgreSQL)
        PDO::ATTR_EMULATE_PREPARES   => false,
    ];

    try {
        return new PDO($dsn, $user, $pass, $opciones);
    } catch (PDOException $e) {
        // Registrar el error en el log del servidor, nunca mostrarlo al usuario
        error_log('[DB Error] ' . $e->getMessage());
        // Mensaje genérico para el usuario
        die('Error de conexión a la base de datos. Inténtalo más tarde.');
    }
}
⚠️ Nunca pongas credenciales directamente en el código fuente Si subes el repositorio a GitHub con la contraseña escrita en el código, cualquier persona podrá verla. Usa siempre variables de entorno (explicadas en la sección 8).

7. CRUD completo con PHP + PDO

CRUD son las cuatro operaciones básicas sobre cualquier base de datos:

OperaciónSQLMétodo HTTP
Create (Crear)INSERTPOST
Read (Leer)SELECTGET
Update (Actualizar)UPDATEPOST / PUT
Delete (Eliminar)DELETEPOST / DELETE
 
<?php
// usuarios_crud.php — Ejemplo completo CRUD con PDO
require_once 'config/database.php';

$pdo = getConexion();

// ════════════════════════════════════════════════════
// READ — Obtener todos los usuarios activos
// ════════════════════════════════════════════════════
// Usamos query() para consultas sin parámetros del usuario
$stmt    = $pdo->query("SELECT id, nombre, email, created_at FROM usuarios WHERE activo = TRUE ORDER BY nombre");
$usuarios = $stmt->fetchAll();  // array con todos los registros

foreach ($usuarios as $u) {
    echo htmlspecialchars($u['nombre']) . ' — ' . htmlspecialchars($u['email']) . "<br>\n";
}

// ════════════════════════════════════════════════════
// READ — Obtener un usuario por ID (con prepared statement)
// ════════════════════════════════════════════════════
// Siempre usa prepare() cuando el valor viene del usuario
$id = (int)($_GET['id'] ?? 0);

$stmt = $pdo->prepare("SELECT * FROM usuarios WHERE id = :id AND activo = TRUE");
$stmt->execute([':id' => $id]);
$usuario = $stmt->fetch();   // un solo registro o false si no existe

if ($usuario) {
    echo "Encontrado: " . htmlspecialchars($usuario['nombre']);
} else {
    echo "Usuario no encontrado";
}

// ════════════════════════════════════════════════════
// CREATE — Registrar un nuevo usuario
// ════════════════════════════════════════════════════
$nombre   = trim($_POST['nombre'] ?? '');
$email    = trim($_POST['email']  ?? '');
$password = $_POST['password']    ?? '';

// NUNCA guardar la contraseña en texto plano; usar password_hash con bcrypt
$hash = password_hash($password, PASSWORD_BCRYPT);

$stmt = $pdo->prepare(
    "INSERT INTO usuarios (nombre, email, password_hash)
     VALUES (:nombre, :email, :password_hash)
     RETURNING id"
);
$stmt->execute([
    ':nombre'        => $nombre,
    ':email'         => $email,
    ':password_hash' => $hash,
]);
$nuevoId = $stmt->fetchColumn();  // el ID generado por SERIAL
echo "Usuario creado con ID: $nuevoId";

// ════════════════════════════════════════════════════
// UPDATE — Actualizar datos de un usuario
// ════════════════════════════════════════════════════
$stmt = $pdo->prepare(
    "UPDATE usuarios
     SET nombre = :nombre,
         email  = :email
     WHERE id = :id"
);
$stmt->execute([
    ':nombre' => 'Nombre Actualizado',
    ':email'  => 'nuevo@uni.es',
    ':id'     => 5,
]);
$filasAfectadas = $stmt->rowCount();  // número de filas modificadas
echo "Filas actualizadas: $filasAfectadas";

// ════════════════════════════════════════════════════
// DELETE — Eliminar un usuario (borrado lógico recomendado)
// ════════════════════════════════════════════════════
// Opción 1: borrado lógico (marca como inactivo, no borra el registro)
$stmt = $pdo->prepare("UPDATE usuarios SET activo = FALSE WHERE id = :id");
$stmt->execute([':id' => 5]);

// Opción 2: borrado físico (elimina el registro definitivamente)
$stmt = $pdo->prepare("DELETE FROM usuarios WHERE id = :id");
$eliminado = $stmt->execute([':id' => 5]);
echo $eliminado ? "Eliminado" : "No se pudo eliminar";
?>

Ejemplo completo: formulario → validación → base de datos

<?php
// guardar_usuario.php — Procesa el formulario de registro

require_once 'config/database.php';

// 1. Verificar que la petición es POST
if ($_SERVER['REQUEST_METHOD'] !== 'POST') {
    header('Location: registro.html');
    exit;
}

// 2. Recoger y limpiar los datos del formulario
$nombre = trim($_POST['nombre'] ?? '');
$email  = trim($_POST['email']  ?? '');
$pass   = $_POST['password']    ?? '';

// 3. Validar los datos
$errores = [];

if (strlen($nombre) < 2 || strlen($nombre) > 100) {
    $errores[] = "El nombre debe tener entre 2 y 100 caracteres.";
}
if (!filter_var($email, FILTER_VALIDATE_EMAIL)) {
    $errores[] = "El email no tiene un formato válido.";
}
if (strlen($pass) < 8) {
    $errores[] = "La contraseña debe tener al menos 8 caracteres.";
}

// 4. Si hay errores, mostrarlos
if (!empty($errores)) {
    foreach ($errores as $e) {
        echo "<p style='color:red'>" . htmlspecialchars($e) . "</p>\n";
    }
    echo "<a href='registro.html'>← Volver</a>";
    exit;
}

// 5. Guardar en la base de datos
try {
    $pdo = getConexion();

    // Comprobar si el email ya está registrado
    $check = $pdo->prepare("SELECT id FROM usuarios WHERE email = :email");
    $check->execute([':email' => $email]);
    if ($check->fetch()) {
        die("Error: Ya existe una cuenta con ese email.");
    }

    // Insertar el nuevo usuario
    $stmt = $pdo->prepare(
        "INSERT INTO usuarios (nombre, email, password_hash)
         VALUES (:nombre, :email, :hash)
         RETURNING id"
    );
    $stmt->execute([
        ':nombre' => $nombre,
        ':email'  => $email,
        ':hash'   => password_hash($pass, PASSWORD_BCRYPT),
    ]);
    $nuevoId = $stmt->fetchColumn();

    // 6. Post/Redirect/Get: redirigir tras éxito para evitar reenvío del formulario
    header('Location: bienvenida.php?id=' . $nuevoId);
    exit;

} catch (PDOException $e) {
    error_log('[Registro] ' . $e->getMessage());
    die("Error interno. Por favor, inténtalo de nuevo.");
}
?>

8. Variables de entorno (.env) — credenciales nunca en el código

Una de las reglas más importantes en desarrollo web es que las credenciales nunca deben estar escritas en el código fuente. Si subes tu código a GitHub con la contraseña de la base de datos, cualquier persona puede verla (incluso si después borras el commit, queda en el historial).

La solución estándar son los archivos .env: un archivo de texto plano en la raíz del proyecto que contiene las variables sensibles. Este archivo nunca se sube al repositorio.

⚠️ Código INCORRECTO — credenciales en el código fuente 
<?php
// ❌ MAL: la contraseña está en texto plano en el código
$pdo = new PDO(
    'pgsql:host=localhost;dbname=mi_proyecto',
    'postgres',
    'miContraseñaSecreta123'  // ← esto NO debe estar aquí
);
✅ Código CORRECTO — credenciales en variables de entorno 
<?php
// ✅ BIEN: se leen de variables de entorno, nunca hardcodeadas
$host = getenv('DB_HOST')     ?: 'localhost';
$name = getenv('DB_NAME')     ?: 'mi_proyecto';
$user = getenv('DB_USER')     ?: 'postgres';
$pass = getenv('DB_PASSWORD') ?: '';

$pdo = new PDO("pgsql:host=$host;dbname=$name", $user, $pass);

Estructura del archivo .env

# .env  ← ESTE ARCHIVO NUNCA SE SUBE A GIT
# Añádelo a .gitignore inmediatamente al crear el proyecto
DB_HOST=localhost
DB_PORT=5432
DB_NAME=mi_proyecto
DB_USER=postgres
DB_PASSWORD=mi_contraseña_segura

# También puedes guardar otras configuraciones sensibles
APP_SECRET_KEY=una_clave_aleatoria_muy_larga
SMTP_PASSWORD=contraseña_del_correo

📌 Cómo cargar el .env en PHP PHP no carga el archivo .env automáticamente. Tienes dos opciones:
  1. En Apache (.htaccess): SetEnv DB_PASSWORD mi_contraseña
  2. Con la librería vlucas/phpdotenv: $dotenv = Dotenv\Dotenv::createImmutable(__DIR__); $dotenv->load(); (instalar con Composer)
  3. Manualmente al inicio del script: parsear el .env con parse_ini_file('.env') y cargar con putenv().
